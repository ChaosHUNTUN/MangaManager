# 2026-08-06

## 阅读器进度恢复问题 — 完整排查与修复

### 现象
进入作品阅读（画廊点击进入 / 阅读模式内切换）时无法恢复数据库中的阅读进度。

### 排查结论
- **后端接口正常**：GET/POST `/api/readingprogress` 读写均验证通过（API 实际端口 **5208**，前端 Vite proxy 转发；README 里的 5000 是旧配置）
- 问题全部在前端 `ReaderLocal.jsx` + `api/reader.js`

### 修复清单（累计 4 处）
1. **双重解包 Bug**：`fetchReadingProgressAbortable` 返回 number(pageIndex)，但调用方 `data?.pageIndex` 二次解包 → 永远得 0。改为 `setInitialPage(pageIndex ?? 0)`
2. **gid 切换残留**：`initialPage` 保留上一部作品值 → 页面先加载完时被旧页码错误恢复。`useEffect([gid])` 中同时清 `setCurrentPage(0)` + `setInitialPage(null)` + `progressRestoredRef=null`
3. **画廊切换把进度清零**：`goPrevGallery`/`goNextGallery` 调用 `saveProgress(currentGid, 0)` 把当前作品进度覆盖为 0。改为 `saveProgress(currentGid, currentPage)`（保存真实页码）
4. **aborted fetch 竞态**：`fetchReadingProgressAbortable` 内部 `catch{return 0}` 让 abort 的旧请求仍 resolve 0 并错误恢复。改为 abort 时 `throw e`，调用方 `.then` 加 `!ctrl.signal.aborted` 守卫 + `.catch(() => {})`

### 关键认知
- React Router 参数变化组件不重挂载 → engine 的 `currentPage` 等 state 会跨作品残留，必须显式重置
- `initialPage` 用 `null`(未加载)/`0+`(已加载) 区分，不能用 0 当哨兵
