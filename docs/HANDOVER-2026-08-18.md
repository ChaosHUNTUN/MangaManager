> 生成时间：2026-08-18（重装电脑前）
> 用途：供新环境/新会话快速恢复工作上下文

## 1. 项目概览

E-Hentai 漫画下载 / 管理 / 阅读工具。三层架构：

| 层 | 技术 | 目录 | 端口 |
|---|---|---|---|
| 前端 | React 19 + Vite | `src/frontend/manga-ui` | 5173 |
| 后端 API | ASP.NET Core 9 + EF Core 9 | `src/backend/MangaManager.Api` | 5208 |
| 桌面控制台 | WPF (.NET) | `src/desktop/MangaManager.Console` | — |
| Python 控制台 | Python 3.12 | `manga_manager.py`（根目录） | — |

- GitHub：https://github.com/ChaosHUNTUN/MangaManager.git
- 分支：`main`（单分支开发）
- 数据库：SQLite（开发） / MySQL（生产，docker-compose 有配置）
- 核心功能：EH 在线搜索下载、本地画廊管理（专辑+排序）、阅读器（缩放/翻页/幻灯片/沉浸模式）、批量导入、标签补全、翻译搜索

## 2. 启动方式

### 主入口（用户日常）
双击 `启动管理工具.bat`（根目录）→ 启动 Python 控制台 → 自动拉起 API + 前端

### 手动启动
```powershell
# API
dotnet run --project src/backend/MangaManager.Api
# 前端（在 src/frontend/manga-ui 下）
npx vite --port 5173
```

### WPF 控制台
`src/desktop/MangaManager.Console`，已实现启动自动检测端口并拉起前后端服务（`Window_Loaded` → `IsPortOpen` + `StartApiAsync/StartUiAsync`），可监控下载任务、系统托盘驻留、单实例运行。

## 6. 重要技术决策与踩坑记录（记忆要点）

### 架构重构（2026-08）
- `EhentaiService` 上帝类拆分为 `EhentaiAuthService`（Cookie 管理）+ `EhentaiBlockedTagService`（屏蔽标签）
- 22 处空 catch 清理（有 logger→LogDebug，无 logger→注释意图）
- `GetGalleryDetailAsync` 拆分、正则常量化

### 下载系统
- 下载取消/移除：`DownloadManager` 用 `_taskCts`（gid→CancellationTokenSource）取消下载线程，linked token + `_tasks.ContainsKey` 判断任务是否存活
- `RemoveTask` 以删 DB 记录为准（历史已完成任务不在内存字典也能删）
- 断点续传：进程崩溃后自动 `pending` 入队，保留 `.progress` 文件续传
- ExHentai 里站下载：`GetPagesAsync` 等方法带 `isExhentai` 参数，页面 HTML 获取失败自动回退里站

### 端口（多次变更的教训）
- 曾用 5000/5001 → 被 NVIDIA(nvcontainer)/Dify 占用 → **现统一 5208**
- `appsettings.json`: `Urls: http://0.0.0.0:5208`
- 前端 `vite.config.js` proxy → `http://localhost:5208`

### 网络连接坑
- `localhost` 会解析到 IPv6 导致超时 → API 调用一律用 `127.0.0.1`
- WPF 控制台 `_apiUrl = "http://127.0.0.1:5208"`
- git 红色 "RemoteException" 是 PowerShell 把 stderr 渲染成错误，**实际 pull/push 成功**（用 `git pull 2>$null` 避免误报）

### WPF 控制台稳定性
- 管道死锁：`Dispatcher.Invoke` → 改 `BeginInvoke`
- `ScrollToEnd` 节流、定时器防重入
- XAML 中重复 `<Style TargetType="ScrollBar">` 会导致控制台无法启动（已删重复）
- `SocketsHttpHandler.ConnectTimeout=2s` 限制连接超时

### 本地画廊元数据 DB 化
- `local_gallery` 表替代纯文件系统扫描，`.meta.json` 保留为备份/详情源
- `GallerySyncService`：启动全量扫描 → 写 DB；FileSystemWatcher 增量；5 分钟一致性检查
- 翻页从磁盘扫描 → SQL LIMIT/OFFSET

### Docker（已放弃，改回控制台）
- Windows Docker Desktop 对大规模目录 bind mount 有 9p 协议限制，只列出部分条目 → 图片/封面丢失
- 改用 Docker volume 后用户仍决定回归控制台

### 设计语言（前端）
- 暗色玻璃系：`#8b7aa0` 薰衣草紫主色、`rgba(13,13,20,0.88)`+blur(20px) 面板、Lucide 1.5px 线性图标、克制动效 cubic-bezier(0.16,1,0.3,1)
- 详规在 `src/visual-test/pages/DesignManifesto.jsx` → `/visual-test/design`
- AntV 图表必须显式传 `theme={{ type:'classicDark', ... }}`，禁用面性图标/高饱和霓虹/emoji 图标

## 8. 重装后恢复步骤（新环境）

```powershell
# 1. 安装依赖
winget install Microsoft.DotNet.SDK.10
winget install OpenJS.NodeJS.LTS
winget install Python.Python.3.12

# 2. 克隆仓库
git clone https://github.com/ChaosHUNTUN/MangaManager.git
cd MangaManager

# 3. 还原前端依赖
cd src/frontend/manga-ui
npm install
cd ../..

# 4. 恢复本地数据（从备份盘/移动硬盘）
#    - manga.db 及 -wal/-shm → src/backend/MangaManager.Api/
#    - G:\学习资料\本子\ 画廊目录 → 新机 G 盘
#    - ehentai_cookies.json → src/backend/MangaManager.Api/
#    - 重建 appsettings.Development.json（含新机下载路径）

# 5. Python 控制台依赖
pip install pystray pillow requests

# 6. 启动
双击 启动管理工具.bat
```
