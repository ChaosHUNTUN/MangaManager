# 移动端适配设计与实施

> 版本：1.0（2026-08-31）
> 目标：让 MangaManager 在手机/窄屏上可用：布局重排、抽屉式导航、触摸目标优化，并提供独立移动端导航外壳。

## 1. 现状分析：移动端的主要问题

### 1.1 布局层面
| 页面 | 问题 |
|---|---|
| 本地画廊 | 根布局 `height:100dvh; overflow:hidden` 固定不滚动；侧边栏仅 **hover 触发**（移动端无入口，专辑功能不可达）；卡片 min-width 250px 在小屏变单列 |
| E-Hentai | 基本可滚动，但顶栏按钮组（Cookie/验证/屏蔽/状态徽章）在窄屏溢出；大量内联样式难以用 CSS 覆盖 |
| 下载监控 | 卡片横向信息行 + 4 个操作按钮，窄屏挤压；无底部留白 |
| 阅读器 | 已有手势/安全区基础（`env(safe-area-inset-*)`），但按钮 30px 偏小、HUD 标题超长溢出 |

### 1.2 交互层面
- 触摸目标：`btn-sm` 等按钮 < 38px，不符合 44px 触控规范
- hover 专属交互：封面悬浮操作层、专辑行操作按钮在触摸设备不可用
- iOS：input 聚焦自动缩放（需 16px 字号）；刘海屏需 `viewport-fit=cover`

## 2. 架构：独立移动端外壳（复用页面与 hooks）

```
App.jsx
├── useIsMobile()（matchMedia ≤768px，响应式）
└── <div class="mobile">          ← 移动端根类，所有适配 CSS 在此作用域下
    ├── Routes（同一套页面与 hooks，不做逻辑复制）
    └── <MobileTabBar/>            ← 独立移动端导航（本地 / 浏览 / 下载）
```

原则：**不复制页面逻辑**；移动端通过"外壳 + CSS 重排"获得独立页面感，后续如需彻底独立的移动端页面，可在同一外壳下替换对应路由组件。

## 3. 已实施调整

### 3.1 移动端外壳
- `useIsMobile`：响应式检测（跟随窗口宽度变化）
- `MobileTabBar`：底部固定标签栏（本地/浏览/下载），阅读器路由自动隐藏；安全区留白 `env(safe-area-inset-bottom)`

### 3.2 页面布局重排（mobile.css，`.mobile` 作用域 + `!important` 覆盖内联样式）
- 页面容器从固定 `100dvh` 改为**可滚动列** + 底部 64px 留白
- 本地画廊：顶栏可换行 + sticky；主内容区恢复滚动；**按钮行修复**（顶栏右侧操作组 `flex-shrink:0` 单行在窄屏溢出 → 移动端按序重排：第一行 标题+操作按钮、第二行 搜索框独占；工具栏取消横向滚动改换行；分页按钮可换行）
- E-Hentai：容器内边距收紧、画廊网格 2 列、顶栏换行；**搜索栏修复**（原为无换行的 flex 行，输入框内联 `min-width:200px` 在窄屏挤压按钮 → 移动端输入框独占整行、控件换行到第二行、Cookie 表单改单列）
- 下载监控：任务行操作按钮 28px → **38px 触控目标**、元数据行允许换行（状态/页数/速度/错误不挤压）、折叠迷你栏可换行（2026-09-01）

### 3.3 专辑侧边栏 → 抽屉
- 侧边栏在移动端固定为 82vw 抽屉（关闭时滑出屏幕、`pointer-events:none` 不挡触摸，打开时盖过标签栏）
- 本地画廊顶栏新增 **☰ 标签** 汉堡按钮（专辑方案废弃后为标签云抽屉，桌面端隐藏）

### 3.4 触摸与移动端细节
- 按钮最小高度 38px；input/select 字号 16px（防 iOS 缩放）
- 隐藏 hover 专属覆盖层；专辑行操作按钮常显
- 阅读器：按钮 40px、HUD 标题截断、缩略图加大、高度 `100dvh`
- viewport 增加 `viewport-fit=cover`

### 3.5 弹窗 → 底部抽屉（2026-09-01）
- 所有 `.modal` 在移动端从居中弹窗改为**底部抽屉**：`align-items:flex-end` + 全宽（`!important` 覆盖内联 `min(…,94vw)`）+ 顶部圆角 + 底部安全区（`env(safe-area-inset-bottom)`）+ `90dvh` 最大高度 + 上滑动画
- 覆盖 TagPicker / TagLibraryModal / BatchTagModal / GalleryDetail / AlbumEditModal 等全部弹窗；内部列表区本就是 `flex:1 + overflowY:auto`，随抽屉高度自适应
- 桌面端行为不变（媒体查询 ≤768px 作用域）

### 3.6 横屏适配（2026-09-01）
- **修复横屏误判**：原 `useIsMobile`/CSS 只认 `≤768px` 宽度，iPhone 横屏（844~932px 宽、高度 ≤500px）会被当成桌面端套短高桌面布局。检测条件改为 `(max-width:768px), (max-width:1024px) and (max-height:500px)`（JS 与 CSS 同步；构建后 LightningCSS 会改写为区间语法 `(width<=…) and (height<=500px)`，现代浏览器均支持）
- 横屏微调（`height≤500px` 作用域）：EH 网格从固定 2 列改 `auto-fill minmax(140px,1fr)`、本地画廊卡片最小宽 150px（更密列）、标签栏 44px、底部留白 48px、缩略图略收窄
